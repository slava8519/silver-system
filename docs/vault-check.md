# Проверка целостности второго мозга

Владелец может узнать, сохранились ли источники и связи после разбора Inbox или ручной правки в Obsidian. Полный проход читает выбранное хранилище и возвращает замечания с координатами. Варианты сравнили по трём критериям — обнаружение старых повреждений, стоимость обработки очереди и сохранность ручных решений.

## Сравнение вариантов

| Вариант | Что обнаружит | Цена и ограничения |
|---|---|---|
| Полный проход до и после каждого разбора, сравнение результатов | Можно выделить замечания, появившиеся между двумя проверками | При каждом документе дважды читается весь архив. В интервале владелец мог сам изменить карточку |
| Проверять запись в момент сохранения | Сразу видна проблема с квитанцией или оригиналом конкретного источника | Утрата старого оригинала или участника плана останется незамеченной до обращения к этим данным |
| Проверять сохранённый источник, а после обхода очереди и по запросу проверять весь vault | Одна запись получает свою проверку, полный проход обнаруживает и старые повреждения | Полный проход читает каждый управляемый оригинал, включая большие вложения. Его результат описывает состояние на момент чтения |

Реализован третий вариант. Пакетная и одиночная обработка возвращают проверку после успешной записи, включая повтор и обработку уточнения. Из `check.scope` видно, что именно проверялось. Проверка работает с Markdown и вложениями в режиме чтения.

## Что проверяется

| Область | Основание для замечания |
|---|---|
| Сохранённый источник | Отсутствует ожидаемая квитанция или оригинал, для одного ID есть несколько архивных файлов или SHA-256 байтов расходится с именем. Контрольная сумма вычисляется и для бинарных вложений |
| Разбор | Повреждена шапка или журнал. Для прерванного разбора указана строка начала. Цитата пакетного разбора отсутствует на указанной строке. Полный проход также сверяет записанные ID получателей и фактов |
| Карточки и планы | Повреждена шапка известного типа, повторяется ID, отсутствует указанный проект, направление, работа или участник. Проверяются снимок закрытого плана, разделы Ганта, записи готовности задачи и история её дат прогноза и завершения. Для выпуска отчёта проверяются границы раздела оснований, запись каждой ссылки и сохранённая версия шаблона. При наличии исходной контрольной суммы проверяется и содержимое этой версии |
| Люди и направления | Проверяются состав команды, выбранный владелец, направление факта, исходная цитата в карточке человека и явно сохранённое правило разбора действующего направления |

Сверка использует ID карточек. Поэтому переименование файла человека сохраняет связь с его фактом. У исправленной формулировки проверяется исходная цитата. У закрытого плана проверяется его собственный снимок. У открытого вопроса владельцу проверяется имеющееся основание, а сам вопрос остаётся в Inbox.

При проверке сразу после записи известна ожидаемая квитанция. Её исчезновение даёт замечание. При полном обходе архивный файл может существовать уже до оформления квитанции. У такого файла проверяются байты и однозначность ID.

Проход охватывает управляемые карточки и архивные файлы с именами по SHA-256. Произвольные ссылки в авторском Markdown, смысл решений и полнота извлечения фактов остаются предметом чтения источника. Пустые направления, задачи без дат, одноимённые люди и несколько версий шаблона допустимы.

## Как воспроизвести

На новом пути создайте учебное хранилище с ИТ-проектами, личными записями и парфюмерией. В нём будут люди, команды и источники со ссылками между записями.

```sh
python3 examples/inbox_vault.py local/CheckPractice --teams
python3 -m second_brain --vault local/CheckPractice check
```

Для пробы в этой учебной копии продублируйте файл одного направления вместе с его YAML-шапкой. Повторите команду. У обеих карточек появится замечание с путём второй. После удаления учебного дубликата замечания исчезнут. Эффект утраты оригинала, повреждения квитанции и ручной правки проверяется также в тестах. [Проверки источников](../tests/test_check_sources.py) · [Проверки карточек](../tests/test_check_records.py)

CLI и кнопка в **Обзор → Проверить хранилище** вызывают одну операцию. В CLI для постраничного просмотра запустите `check --snapshot new --limit 5`. Результат содержит время завершения `checkedAt` и идентификатор `snapshot`. Подставьте его в `check --snapshot ID --limit 5 --offset 5`, чтобы открыть следующую страницу того же прохода. В браузере страницы сохраняют это время и ID. После исправления файла нажмите **Проверить снова**. Самостоятельная команда `check` каждый раз читает текущее состояние хранилища.

Кеш пользователя хранит восемь последних результатов для каждого пути хранилища. В него входят время, счётчики и замечания с координатами. Архивные вложения и тексты цитат остаются в хранилище. Если кеш недоступен, первая страница показывает результат завершённой проверки и предупреждение о повторном чтении при перелистывании. Статус `ok` означает успешное прохождение перечисленных проверок, `issues` — обнаруженные нарушения, `incomplete` — неполный доступ к данным. Успешная запись Inbox возвращает свою квитанцию при любом результате последующей проверки.
