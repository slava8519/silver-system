# Второй мозг

Локальное хранилище Markdown для разных сторон жизни. Прототип умеет создавать направления, заметки и проекты, разбирать входящие документы и вести одну карточку человека для нескольких направлений. У подтверждённых фактов сохраняются источники. Три синтетических примера живут рядом в одном хранилище. У первого направления два ИТ-проекта, у второго бытовая памятка, у третьего журнал парфюмерных наблюдений.

**Все имена папок — на английском.** Документация и заметки могут быть на русском или другом выбранном языке.

Основная модель: направления задают персонализацию; заметки, люди и работы сохраняют знания и состояние; планы, отчёты, OKR и Гант организуют и показывают эти данные. Один человек может пользоваться системой для разных сторон жизни без выбора класса «личный/менеджерский».

**Повседневная работа идёт в Codex и Obsidian.** В Obsidian вы правите Markdown напрямую. В Codex можно поручить поиск решения или обновление карточки. В рабочей оболочке вы управляете теми же записями, видите связи и текущее состояние проектов. Для первого знакомства есть отдельный иллюстрированный деморежим.

## Как ИИ выбирает навык

Опишите задачу обычной фразой и укажите хранилище. Браузер вызывает операции Python через локальный HTTP. ИИ выбирает короткий навык и вызывает те же операции через CLI. Например, на вопрос о решениях двух проектов команда `ask --brief` возвращает выдержку и координаты источника для каждого найденного решения. Открывать целую карточку полезно, когда для ответа нужен дополнительный контекст.

## Открыть рабочее хранилище

В настольном Obsidian нажмите **Второй мозг** на левой ленте. Кнопка запускает админку текущего хранилища и открывает её во вкладке. **Открыть в браузере** переносит текущий раздел в системный браузер. **Остановить админку** выключает сервер, когда вы возвращаетесь к работе с Markdown или диалогу с Codex или Claude. [Подключение и настройки плагина](plugins/obsidian-gantt/README.md)

Для работы нужны Python 3.9+ и SQLite с FTS5. Если папки `local/WorkshopVault` ещё нет, создайте учебное хранилище командой `python3 examples/working_vault.py local/WorkshopVault`. Его стартовая страница в Obsidian — `local/WorkshopVault/Home.md`. Запустите оболочку из корня проекта.

```sh
python3 -m second_brain --vault local/WorkshopVault work
```

В шапке рабочей оболочки и деморежима кнопка **ⓘ О системе** открывает техническое руководство. В начале схемой показаны разбор входящих, место хранения каждой записи и данные, на которые опираются Codex, Гант, недельный обзор и OKR. Выбор узла открывает его объяснение. В конце руководства есть сценарий для показа на учебной команде. [Открыть карту движения информации](http://127.0.0.1:8766/about.html#system-map)

На главной в **Состоянии направлений** видны «Коротко», последнее событие и его источник. Собственная сводка направления имеет приоритет. Если её ещё нет, обзор показывает до двух выдержек из связанных записей. Нажмите на название направления, чтобы открыть карточку, или на источник, чтобы перейти к строке Markdown. В разделе **Управление вторым мозгом** можно скопировать готовый запрос для Codex вместе с путём к текущему хранилищу. [Открыть рабочий обзор](http://127.0.0.1:8766/#overview)

На карте связей выберите «Городская типография», затем один из двух проектов. Кнопка **Открыть карточку** ведёт к самой записи. У «Меридиана» заполнены статус, срок и следующий шаг. У «Палитры» при создании указан только статус. В разделе «Карточки» можно добавить своё направление и проект, изменить название или перенести проект в другое направление. ID проекта сохраняется. [Открыть карту связей](http://127.0.0.1:8766/#map)

В чате Codex спросите «Что решили по Меридиану и Палитре?». У каждого решения свой источник. Команда `ask` вернёт выдержки, ID, пути и номера строк, в том числе при остановленном сервере. Для поиска в одном направлении добавьте `--direction ID_НАПРАВЛЕНИЯ`.

```sh
python3 -m second_brain --vault local/WorkshopVault ask "Что решили по Меридиану и Палитре?"
python3 -m second_brain --vault local/WorkshopVault overview
```

Чтобы воспроизвести учебное наполнение в новом каталоге, выполните `python3 examples/working_vault.py local/WorkshopCopy` и подставьте этот путь в команды выше. [Генератор учебных данных](examples/working_vault.py)

Для своего существующего хранилища укажите его путь после `--vault`. Карточки направлений, проектов и заметок лежат в `Directions`, `Projects` и `Notes`. Карточки людей хранятся в `People`. Пустое хранилище сначала подготовьте командой `init`. Демонстрационные записи создаются отдельно.

## Карта связей

Начните с направления или найдите карточку по названию либо другому имени. Например, «Маяк» открывает проект «Переезд базы заказов» в учебных планах. Каждая группа показывает количество прямых связей. Небольшие группы видны сразу. Раскройте большую группу, чтобы посмотреть пять записей или найти нужную внутри неё. Состав папок доступен в рабочем обзоре.

Выберите «Проверить восстановление базы», чтобы увидеть, в какие планы входит эта работа. У каждой связи есть **Основание** с путём и строкой Markdown. Выбор соседней карточки показывает её связи. Кнопка браузера «Назад» возвращает к прежнему поиску и странице. Из открытой карточки или Ганта можно начать с действия **Показать связи**. В шапке карты кнопка **О разделе** открывает три учебных примера и объясняет, как читать связи закрытых планов. [Учебные данные](examples/planning_vault.py) · [Команды карты для Codex](.agents/skills/brain-overview/SKILL.md)

## Одна задача в двух планах

В направлении можно вести заметки и обычные дела. Если появляется конечный результат, к нему можно завести проект и связать с ним задачи. Владелец выбирает названия и состав планов. Например, задача проекта может одновременно входить в план запуска и в план недели. ОКР и форматы управления подключаются по потребности. Гант и таблица плана показывают сроки уже заведённых работ.

Для воспроизведения с исходными учебными датами создайте отдельное хранилище из корня программы.

```sh
python3 examples/planning_vault.py local/PlanningPractice
```

Откройте Codex в проекте и скажите **«В local/PlanningPractice перенеси срок задачи „Проверить восстановление базы“ проекта „Маяк“ на 27 ноября 2026 года и покажи дату в обоих планах»**. Если хотите сначала посмотреть последствия, попросите **«Покажи, что изменится»**. Предпросмотр читает текущую дату и перечисляет затронутые планы. При переносе срок и запись истории сохраняются вместе в карточке задачи.

В `Tasks/` лежит одна Markdown-карточка каждой задачи. В `Plans/` хранятся упорядоченные ссылки с ID. В Obsidian можно открыть карточку задачи из любого её плана. В Codex команда `plan-show ID` показывает актуальные даты активного плана или сохранённые даты закрытого цикла. Команды `task-list`, `plan-list` и `task-history` помогают найти запись и проверить изменение. В учебном хранилище тот же сценарий доступен для подготовки к поездке и кедровых проб. [Навык планирования](.agents/skills/brain-plan/SKILL.md) · [Генератор трёх примеров](examples/planning_vault.py)

## Открыть Гант

Для первого запуска создайте учебное хранилище командой `python3 examples/gantt_vault.py local/GanttLab`. Затем запустите `python3 -m second_brain --vault local/GanttLab work --port 8768`.

В рабочей админке выберите **Планы**. Откроется каталог **Проекты и Гант** с фильтром по планам. Найдите план по названию и откройте его Гант. В настольном Obsidian откройте команду **Открыть Гант**. Обе вкладки работают с одной карточкой задачи. Выберите строку, чтобы посмотреть согласованный срок, текущий прогноз и факт завершения, проверить основания или исправить сводку. В меню «Изменить даты» можно перенести прогноз отдельно от согласованного срока. В Codex попросите **«Разбери ручные правки Ганта в local/GanttLab»**.

Чтобы увидеть последствия переноса, выберите «Проверить восстановление базы» и нажмите **Что если…**. Введите предполагаемую дату завершения. В расчёте появятся проверка, зависимая веха «Готовность к переключению» и запас дней до согласованной даты каждой из них. То же можно спросить в Codex фразой **«В GanttLab что изменится, если проверку восстановления базы закончим 2 декабря 2026 года?»**. Прогнозы попадают в карточки после подтверждения. [Вехи и зависимости](docs/gantt.md#вехи-и-зависимости)

В списке планов откройте «План недели» и нажмите **Закрыть цикл…**. После подтверждения попросите Codex создать «План следующей недели» и включить в него существующую задачу «Проверить восстановление базы». Если изменить прогноз в новом плане, в закрытом Ганте останется дата на момент закрытия. [Как закрыть цикл](docs/gantt.md#закрытие-цикла)

## Отчёты и шаблоны

В **Отчёты → Шаблоны** доступны 11 встроенных форматов. Они входят в поставку, открываются в пустом хранилище и остаются доступны после действия **Убрать демоданные**.

| Шаблон | Пример запроса в Codex |
|---|---|
| Итоги недели по направлению | «Подведи итоги недели с 16 по 22 ноября по направлению “Парфюмерия”. Что изменилось и какой вопрос остался открытым?» |
| Подготовка к встрече 1:1 | «Подготовь меня к разговору один на один с Дарьей. К каким договорённостям стоит вернуться и о чём спросить?» |
| Повестка созвона по теме | «Собери повестку созвона о месте встречи перед поездкой. Что уже известно и что нужно решить вместе?» |
| Итоги встречи | «Собери итоги разговора о поездке. Где договорились встретиться и кому поручили бронь?» |
| Записка для принятия решения | «Сравни два маршрута по нашим записям. Какой лучше подходит группе и что может изменить выбор?» |
| Результаты проверки | «Что показала проверка восстановления базы на стенде? Укажи условия и сравни замер с ориентиром». |
| Статус проекта | «Подготовь очередной статус проекта “Маяк”. Что изменилось с прошлого выпуска и где нужна помощь?» |
| Ретроспектива завершённой работы | «Подведи итоги завершённой серии кедровых проб. Что стоит повторить и что лучше изменить в следующей серии?» |

В библиотеке также есть «Дайджест команды», «Повестка встречи» и «Краткий отчёт».

Во вкладке **Отчёты** откройте выпуск, чтобы прочитать его, проверить основания и скопировать обычный текст для чата или исходный Markdown. Для подготовки выпуска по записям выберите шаблон и скопируйте запрос для Codex. В форме также можно самостоятельно написать текст, приложить строку источника и открыть предпросмотр. [Навык отчётов](.agents/skills/brain-report/SKILL.md)

Если основанием отчёта служит статус, срок или следующий шаг проекта, ссылка открывает соответствующее поле карточки. После изменения значения отчёт сохраняет исходную цитату и показывает, что прежнее основание больше недоступно. Для старого выпуска, в котором строка поля и строка истории неразличимы, также потребуется сверка.

В разделе **Шаблоны** задайте адресата, правила отбора материала и структуру текста. Сохранение изменений создаёт новую версию. В выпуске указана версия, по которой его подготовили. Для серии выберите шаблон, периодичность и дату начала. На странице серии видны очередной период и предыдущие выпуски. Для автоматической подготовки скопируйте запрос на настройку расписания в Codex. В нём можно выбрать время и часовой пояс запуска. [Серии, расписание и версии](.agents/skills/brain-report/references/formats.md)

В отдельном учебном хранилище есть дайджест о восстановлении базы, повестка перед поездкой и отчёт по кедровой пробе. В дайджесте за 16–22 ноября измерение проведено 19 ноября, а следующий шаг согласован 23 ноября. Поле **Данные на** фиксирует дату актуальности сведений независимо от периода отчёта. Раскройте источники и сравните замер с ориентиром. Ссылка из выпуска откроет первую версию его шаблона. Выберите вторую и посмотрите, как изменилось правило для числовых сравнений.

```sh
python3 examples/report_vault.py local/ReportsLab
python3 -m second_brain --vault local/ReportsLab work --port 8775
```

[Открыть учебные отчёты](http://127.0.0.1:8775/#reports) · [Как проверять факты и редактировать выпуск](.agents/skills/brain-report/references/review.md)

## Недельный обзор

В Codex попросите **«В GanttLab собери обзор за 16–22 ноября по закрытому “Плану недели”. Сохрани его со ссылками на Гант и записи»**. В Obsidian выпуск появится в `Reports/`. Его также можно открыть по названию в шапке закрытого Ганта.

В разделе «События недели» каждое утверждение ведёт к датированной записи или к подтверждённому завершению. Раздел «На момент закрытия» показывает, что было известно о работах, когда закрыли план. Ссылка «Гант» выделяет исходную строку, «Источник» открывает подтверждающий фрагмент. Рядом есть ссылки на Markdown для чтения в Obsidian. Название и группировку следующих выпусков можно задать в `Settings/Formats/Weekly.md`. [Навык и команды](.agents/skills/brain-weekly-review/SKILL.md)

## Проектная деятельность

Вкладка **Проекты и Гант** показывает два вида записей — проекты и планы. Выберите **Гант проекта**, чтобы увидеть все его задачи и вехи, включая работы вне планов. В **Ганте плана** виден состав выбранного периода, который может охватывать несколько проектов. При желании к плану добавляют цели и КР. Раскрывая **Связанные планы** у проекта, можно увидеть, какие периоды используют его работы и сколько из них участвует в КР.

В **Проектах плана** можно включить проект ещё до появления задач, а позже выбрать существующую работу для Ганта. Если снять явное включение, выбранные работы и ссылки из КР сохраняются. Такие правки из веба можно разобрать в Codex просьбой **«Разбери ручные правки плана»**. Кнопка **О разделе** в каталоге открывает схему связей и пример годового проекта с квартальным срезом. [Навык планирования](.agents/skills/brain-plan/references/gantt.md#проект-и-его-планы)

У проекта могут быть собственные начало и срок, даже пока в нём нет задач. Шкала **Весь проект** охватывает известные даты, а **Год** показывает календарные месяцы. Новую задачу или веху можно сразу добавить в проект. В чате можно попросить **«Покажи весь проект и отдельно те работы, которые вошли в квартальные КР»**. [Команды для Codex](.agents/skills/brain-plan/references/gantt.md#проект-и-его-планы)

Самостоятельный пример создаётся командой `python3 examples/project_activity_vault.py local/ProjectPractice`. Запустите `python3 -m second_brain --vault local/ProjectPractice work --port 8773` и откройте «Обновление мастерской — 2026». В годовом проекте четыре работы, две связаны с квартальным КР. [Открыть каталог](http://127.0.0.1:8773/#activity)

### Коротко и события проекта

Откройте карточку проекта, чтобы увидеть **Коротко** и **Историю событий**. В Ганте проекта над работами видны та же сводка и последнее событие. Нажмите на источник под записью, чтобы прочитать цитату и открыть строку оригинала или заметки. Через **Изменить** в карточке можно сохранить свою формулировку сводки.

У направления без собственного правила по умолчанию включены **События проекта** и **Коротко по событиям проекта**. Скажите «Разбери всё новое». Если во встрече или переписке однозначно назван проект, Codex сохранит подтверждённое изменение со ссылкой на цитату и обновит сводку, когда факт меняет текущее положение. При неизвестной дате запись останется без даты. Новые события можно добавлять и при ручной сводке владельца. В **Входящие → Правила направлений** можно оставить только события или выключить обе опции. Для направления с сохранённым правилом действует выбранный владельцем набор. [Правила разбора](.agents/skills/brain-intake/references/queue.md)

В Codex спросите **«Где мы сейчас по Маяку и что изменилось?»**. Ответ показывает текущую формулировку и недавние события с координатами источников. Для просмотра всей истории используется `project-updates ID` с постраничным чтением. Текст сводки и событий также доступен в полнотекстовом поиске после сохранения карточки. [Команды карточки](.agents/skills/brain-record/SKILL.md)

Скажите **«Обнови все сводки и истории»**, чтобы за один проход сверить карточки всего ваулта. Из терминала для учебного хранилища выполните `python3 -m second_brain --vault local/ProjectUpdatesLab refresh-all`. Команда использует подтверждённые основания для «Коротко» и событий проектов и задач, фиксирует ручные уточнения общих фактов о людях и актуализирует поиск. В ответе видны число изменённых карточек, новые события и замечания с путями. Для новых материалов в Inbox есть отдельная команда **«Разбери всё новое»**.

Для просмотра на синтетических данных создайте учебное хранилище в новой папке. В каталоге **Проекты и Гант** откройте проект **Переезд базы заказов** («Маяк»). Три сообщения из Inbox уже разобраны, у каждого события можно открыть оригинал.

```sh
python3 examples/gantt_vault.py local/ProjectUpdatesLab --project-updates
python3 -m second_brain --vault local/ProjectUpdatesLab work --port 8774
```

## Цели и ключевые результаты

В разделе **Проекты и Гант** включите фильтр **С OKR**. Нажмите название плана, чтобы открыть его доску целей. В обзоре периода видны цели и их КР, известные результаты проверок, пороги и готовность инициатив. Выберите КР, чтобы открыть его критерии, источники и вклады работ. Формы изменений находятся в карточке. В **Общем Ганте** можно свернуть план до уровня КР или раскрыть конкретную инициативу и её вехи.

Числовой критерий хранит базу, порог с направлением сравнения и датированные измерения. У качественного условия своя проверка с ответом да/нет и цитатой. При записи замера в браузере выберите заметку или проект, затем строку с основанием. Готовность инициатив рассчитывается по весам и оценкам работ. Для среднего по периоду должны быть рассчитаны все цели. Старые снимки показывают данные, сохранённые при их закрытии. [Правила и команды готовности](.agents/skills/brain-plan/references/okr-progress.md)

Для отдельной практики выполните `python3 examples/okr_review_vault.py local/OKRPracticeReview`, затем `python3 -m second_brain --vault local/OKRPracticeReview work --port 8772`. В учебном КР 1.2 исходный замер составляет 11%, ориентир — ≤5%, а пять инициатив дают готовность 50,5%. В источниках примера есть отдельный учебный протокол для ввода нового замера и подтверждения участия склада. [Открыть учебный раздел](http://127.0.0.1:8772/#okr)

Чтобы завести свой квартал, выберите существующий план или нажмите **Создать план периода**. В обзоре выберите **Добавить цель**, укажите направление и сформулируйте желаемый исход. Добавьте к цели измеримые или качественные ключевые результаты. Фактическое значение появится после записи наблюдения с датой и источником.

Свяжите КР с существующими работами. В Ганте общая для двух КР задача имеет одну календарную полосу, а из второй ветви доступна та же карточка. Фильтр позволяет выбрать цель, КР или работы без прямой связи с КР. Закрытие периода фиксирует критерии и их проверки, веса, известную готовность и дерево работ с датами.

Если папки `local/OKRLab` ещё нет, создайте учебное хранилище командой `python3 examples/okr_vault.py local/OKRLab`. В Obsidian откройте его `Home.md`. Для браузерного сценария запустите оболочку из папки программы.

```sh
python3 -m second_brain --vault local/OKRLab work --port 8770
```

В новом учебном примере выберите **OKR на IV квартал** и откройте результат «Время восстановления базы». Протокол «Маяка» за 22 ноября фиксирует 18 минут при ориентире 15 минут. Общий Гант показывает работы двух проектов, личное дело и одну задачу без связи с КР. В ранее созданных учебных хранилищах результаты доступны в разделе **Результаты вне планов**. В карточке такого КР можно выбрать, к какой цели его отнести. [Открыть результаты](http://127.0.0.1:8770/#okr)

В Codex спросите **«В local/OKRLab какое время восстановления базы у Маяка? Покажи замер, ориентир и строку протокола»**. Для самостоятельного опыта на чистой копии выполните `python3 examples/okr_vault.py local/OKRPractice`. [Команды записи и чтения](.agents/skills/brain-plan/references/okr.md) · [Генератор примеров](examples/okr_vault.py)

## Добавить материал во входящие

Откройте вкладку **Входящие**. Вставьте текст, при желании укажите название и нажмите **Сохранить текст**. Для документов и изображений нажмите **Выбрать файлы** или перетащите их в форму. Скриншот переписки можно вставить прямо на вкладке сочетанием ⌘V или Ctrl+V. После сохранения вы увидите точный путь в своём хранилище. [Открыть входящие](http://127.0.0.1:8766/#inbox)

Текст сохраняется в Markdown, файлы — в исходном виде. При совпадении имён новая копия получает номер. Оболочка принимает до 1 МиБ вставленного текста и до 32 МиБ на файл. Материалы остаются в очереди до команды «Разбери всё новое» в Codex. В чате также можно поручить само сохранение. Для этого есть команды `inbox-text` (текст из stdin, необязательный `--title`) и `inbox-file "путь к файлу"`.

В WorkshopVault Дарья Миронова отвечает за цветопробу в «Городской типографии» и ведёт запись звукового маршрута в «Полевых записях». Откройте её карточку и сравните две роли со строками 5 и 6 одной встречи. [Люди](http://127.0.0.1:8766/#people) · [Учебный протокол](examples/meeting.md)

Сохраните как общий факт дословный фрагмент строки 5 о месте записи. В карточке можно уточнить формулировку и посмотреть историю. Источник ведёт к первоначальной цитате. [Входящие](http://127.0.0.1:8766/#inbox)

Те же данные доступны из Codex. Примеры команд запускаются из корня программы.

python3 -m second_brain --vault local/WorkshopVault inbox-read "Inbox/Сверка перед выездом.md" --start 5 --limit 1

[Пример разбора](.agents/skills/brain-intake/SKILL.md) · [Команды для карточки человека](.agents/skills/brain-person/SKILL.md)

При разборе текстовой встречи точная копия попадает в `Sources/Originals`, ссылки на подтверждённые строки и карточки — в `Sources/Processed`. Входящий файл сохраняется и помечается как обработанный по содержимому. Повтор распознаёт тот же материал после переименования.

В рабочем контексте карточка показывает общие факты. Личные наблюдения открываются по явному выбору в карточке человека или через `person ID --personal`. Общая ссылка показывает только разрешённую цитату, даже если на той же строке есть личная подробность. При разборе владелец может отдельно открыть полный оригинал. Это режимы чтения внутри локального хранилища одного владельца, у которого есть доступ к файлам в Obsidian.

## Разобрать всё новое

В чате Codex с выбранным хранилищем напишите **«Разбери всё новое»**. Если в рабочей папке несколько хранилищ, назовите нужное, например «Разбери всё новое в local/InboxLab». Очередь охватывает `Inbox/` и его подпапки. Markdown и TXT в UTF-8 читаются построчно. Для читаемого скриншота Codex может сохранить расшифровку и разобрать её по тем же правилам. Из расшифровки можно открыть исходное вложение. Если содержимое недоступно или требует пояснения, у владельца появится вопрос.

Для записи событий и «Коротко» нового направления достаточно стандартного правила. В **Входящие → Правила направлений** владелец может задать свои условия, выбрать поля проектов и доступ к фактам о людях. Собственные правила хранятся в Markdown в `Settings/Intake/`. Спорные фрагменты остаются в **Вопросах владельцу**. [Входящие](http://127.0.0.1:8766/#inbox)

У подтверждённого изменения есть карточка и строка неизменённого оригинала. Вопрос владельцу тоже привязан к конкретной строке. Ответьте на него в оболочке или попросите Codex передать уточнение, затем снова скажите «Разбери всё новое». Ранее подтверждённые части документа сохранятся. Тот же материал после переименования распознаётся по содержимому.

Для самостоятельной пробы можно создать отдельное хранилище с тремя настроенными направлениями. Четыре новых файла проверяют два ИТ-проекта, личную договорённость, парфюмерную серию и срок без названия проекта. Генератор требует свободный путь. [Учебное наполнение](examples/inbox_vault.py)

```sh
python3 examples/inbox_vault.py local/InboxPractice
python3 -m second_brain --vault local/InboxPractice work --port 8768
```

В Codex укажите `local/InboxPractice` и запустите разбор. Посмотрите результат в [обзоре](http://127.0.0.1:8768/#overview), [карточках людей](http://127.0.0.1:8768/#people) и [вопросах владельцу](http://127.0.0.1:8768/#inbox?view=triage). В учебном примере можно ответить, что срок относится к «Маяку», и посмотреть, как после второго обхода изменится срок этого проекта.

## Проверить хранилище

Попросите Codex **«Проверь второй мозг»** и укажите хранилище. В рабочей оболочке откройте **Обзор → Проверить хранилище**. Для каждой найденной проблемы видны причина и путь, а для ошибки в тексте — также номер строки. На следующих страницах показаны замечания того же прохода. Время его завершения указано рядом с результатом. После ручного исправления нажмите **Проверить снова**.

```sh
python3 -m second_brain --vault local/InboxPractice check --snapshot new --limit 5
```

Для следующей страницы подставьте полученный ID в `check --snapshot ID --limit 5 --offset 5`. Для разовой проверки текущих файлов достаточно команды `check`.

После каждого сохранённого разбора Inbox система проверяет файл разбора и архивный оригинал, в том числе вложение. После непустого обхода очереди Codex также запускает проверку всего хранилища. Она находит повторяющиеся ID, потерянные связи между карточками, ошибки в правилах направлений, расхождения цитат и изменения оригиналов. Проверка работает в режиме чтения. Число замечаний и область проверки видны отдельно от результата записи и вопросов владельцу. [Как читать результат](.agents/skills/brain-vault/SKILL.md#проверить-хранилище) · [Сравнение вариантов и границы проверки](docs/vault-check.md)

## Пройти деморежим

Откройте [локальный путеводитель](http://127.0.0.1:8765/). Для запуска или после перезагрузки компьютера выполните из корня проекта:

```sh
python3 -m second_brain --vault local/DemoVault demo
```

При первом запуске создаётся отдельное хранилище с тремя примерами. Нажмите «Начать знакомство» или выберите любую карточку. Выберите вопрос, прочитайте ответ и нажмите «Открыть источник». Путеводитель перечитает файл и выделит нужную строку. Чтобы пройти направление, откройте источники всех его вопросов.

На главной есть поле [«Спросить по записям»](http://127.0.0.1:8765/#ask). Введите, например, «Что мы решили по Маяку и Орбите?». Поиск охватывает проекты и заметки трёх демонстрационных направлений. В ответе у каждого проекта своя выдержка из Markdown и ссылка с номером строки. Нажатие раскрывает фрагмент прямо под ответом. Эту же ссылку можно скопировать или открыть в отдельной вкладке, чтобы прочитать запись целиком. Свободные вопросы доступны и со страницы каждого примера.

В конце нажмите «Добавить своё направление», введите название темы, заголовок заметки и факт. Задайте вопрос по своей заметке. Записи сохраняются в `local/DemoVault/Directions` и `local/DemoVault/Notes` и доступны в «Моих направлениях» после перезапуска. Отметки о просмотре сохраняются в этом браузере. Для работы путеводителя достаточно локальных файлов и поиска, учётная запись ИИ не требуется.

### Убрать демоданные и оставить своё

На главной путеводителя или в разделе **Обзор** учебной рабочей копии нажмите **Убрать демоданные**. Перед подтверждением видно, сколько учебных файлов попадёт в архив и сколько останется в работе. Можно отменить действие. После подтверждения по тому же адресу откроется рабочая оболочка этой папки.

Свои записи, изменённые учебные карточки и материалы, на которые опираются ваши записи, остаются в работе. Убранные примеры сохраняются одним ZIP-файлом в `Archive/DemoCleanup/`. Внутри ZIP у каждого файла остаётся его исходный путь. При следующем запуске `demo` для этой папки снова откроется рабочая оболочка. Для другого существующего хранилища укажите его путь в команде `python3 -m second_brain --vault "/путь/к/хранилищу" work`.

В Codex можно попросить «Покажи, какие демоданные можно убрать из моей учебной копии». [Команды работы с хранилищем](.agents/skills/brain-vault/SKILL.md)

## Попробовать через команды

Команды запускаются из корня проекта. Нужны Python 3.9+ и SQLite с FTS5. На этом этапе используется стандартная библиотека Python.

```sh
python3 -m second_brain --vault "local/My Examples" examples
python3 -m second_brain --vault "local/My Examples" search "Что проверяет команда Маяка перед переключением?"
```

Откройте `Home.md` созданного хранилища для перехода ко всем трём направлениям. В выдаче команды `search` есть путь и номера строк. Для этого примера исходную строку можно прочитать так:

```sh
python3 -m second_brain --vault "local/My Examples" read "Projects/Переезд базы заказов.md" 11 11
```

В новом чате с ИИ, который умеет выполнять локальные команды, укажите папку проекта и путь к созданному хранилищу. Например:

> В этом проекте пользуйся командой `python3 -m second_brain --vault "local/My Examples"`. Какой вход согласован для первого запуска Орбиты? Найди запись через `search`, проверь фрагмент через `read` и укажи файл и строки. Если запрошенного факта в источнике нет, скажи об этом.

Затем можно спросить, где лежит запасной ключ, или что осталось у Кедра через сутки. В последнем случае важно сверить время наблюдения с вопросом. Для новой чистой копии примеров выберите другой путь. Команда `examples` создаёт только новое хранилище.

## Добавить свою тему

В хранилище примеров или в своей пустой папке доступны те же операции. Для своей папки из корня проекта выполните:

```sh
python3 -m second_brain --vault "local/My Vault" init
python3 -m second_brain --vault "local/My Vault" create direction "Астрономия"
```

Скопируйте значение `id` созданного направления вместо `ID_НАПРАВЛЕНИЯ`:

```sh
python3 -m second_brain --vault "local/My Vault" create note "Первое наблюдение" --direction ID_НАПРАВЛЕНИЯ --body "Взял лунный фильтр."
python3 -m second_brain --vault "local/My Vault" search "Какой фильтр я взял?"
```

Для проекта укажите тип `project`. Для другого знакомого названия добавьте `--alias`. Команда `list --direction ID_НАПРАВЛЕНИЯ` выводит записи одного направления. Свободную заметку можно создать без направления. ИИ может выполнить эти же шаги по просьбе «Заведи направление про астрономию и запиши моё первое наблюдение».

Файлы можно редактировать вручную. Для изменения через команды сначала используйте `show ID`, затем `update ID --revision ВЕРСИЯ --body "Новый полный текст"`. Изменение требует прочитанной версии и сохраняет поля шапки. Поиск охватывает карточки с ID в `Directions`, `Notes` и `Projects`. Индекс лежит в `.second-brain/` внутри хранилища и восстанавливается командой `rebuild`.
