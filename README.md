# Второй мозг

Локальное хранилище Markdown для разных сторон жизни. Прототип умеет создавать направления, заметки и проекты, разбирать входящие документы и вести одну карточку человека для нескольких направлений. У подтверждённых фактов сохраняются источники. Три синтетических примера живут рядом в одном хранилище. У первого направления два ИТ-проекта, у второго бытовая памятка, у третьего журнал парфюмерных наблюдений.

**Все имена папок — на английском.** Документация и заметки могут быть на русском или другом выбранном языке.

Основная модель: направления задают персонализацию; заметки, люди и работы сохраняют знания и состояние; планы, отчёты, OKR и Гант организуют и показывают эти данные. Один человек может пользоваться системой для разных сторон жизни без выбора класса «личный/менеджерский».

**Повседневная работа идёт в Codex и Obsidian.** В Obsidian вы правите Markdown напрямую. В Codex можно поручить поиск решения или обновление карточки. В рабочей оболочке вы управляете теми же записями, видите связи и текущее состояние проектов. Для первого знакомства есть отдельный иллюстрированный деморежим.

## Как ИИ выбирает навык

Опишите задачу обычной фразой и укажите хранилище. Браузер вызывает операции Python через локальный HTTP. ИИ выбирает короткий навык и вызывает те же операции через CLI. Например, на вопрос о решениях двух проектов команда `ask --brief` возвращает выдержку и координаты источника для каждого найденного решения. Открывать целую карточку полезно, когда для ответа нужен дополнительный контекст.

## Открыть рабочее хранилище

Для работы нужны Python 3.9+ и SQLite с FTS5. Если папки `local/WorkshopVault` ещё нет, создайте учебное хранилище командой `python3 examples/working_vault.py local/WorkshopVault`. Его стартовая страница в Obsidian — `local/WorkshopVault/Home.md`. Запустите оболочку из корня проекта.

```sh
python3 -m second_brain --vault local/WorkshopVault work
```

В шапке рабочей оболочки и деморежима кнопка **ⓘ О системе** открывает техническое руководство. В начале схемой показаны разбор входящих, место хранения каждой записи и данные, на которые опираются Codex, Гант, недельный обзор и OKR. Выбор узла открывает его объяснение. В конце руководства есть сценарий для показа на учебной команде. [Открыть карту движения информации](http://127.0.0.1:8766/about.html#system-map)

Откройте [рабочий обзор](http://127.0.0.1:8766/). На [карте связей](http://127.0.0.1:8766/#map) выберите «Городская типография» и откройте один из двух проектов. В обзоре нажмите на источник статуса, срока или следующего шага, чтобы увидеть точную строку Markdown. У «Меридиана» заполнены все три поля. У «Палитры» при создании указан только статус. В разделе «Карточки» можно добавить своё направление и проект, изменить название или перенести проект в другое направление. ID проекта сохраняется.

В чате Codex спросите «Что решили по Меридиану и Палитре?». У каждого решения свой источник. Команда `ask` вернёт выдержки, ID, пути и номера строк, в том числе при остановленном сервере. Для поиска в одном направлении добавьте `--direction ID_НАПРАВЛЕНИЯ`.

```sh
python3 -m second_brain --vault local/WorkshopVault ask "Что решили по Меридиану и Палитре?"
python3 -m second_brain --vault local/WorkshopVault overview
```

Чтобы воспроизвести учебное наполнение в новом каталоге, выполните `python3 examples/working_vault.py local/WorkshopCopy` и подставьте этот путь в команды выше. [Генератор учебных данных](examples/working_vault.py)

Для своего существующего хранилища укажите его путь после `--vault`. Карточки направлений, проектов и заметок лежат в `Directions`, `Projects` и `Notes`. Карточки людей хранятся в `People`. Пустое хранилище сначала подготовьте командой `init`. Демонстрационные записи создаются отдельно.

## Одна задача в двух планах

В направлении можно вести заметки и обычные дела. Если появляется конечный результат, к нему можно завести проект и связать с ним задачи. Владелец выбирает названия и состав планов. Например, задача проекта может одновременно входить в план запуска и в план недели. ОКР и форматы управления подключаются по потребности. Гант и таблица плана показывают сроки уже заведённых работ.

Для воспроизведения с исходными учебными датами создайте отдельное хранилище из корня программы.

```sh
python3 examples/planning_vault.py local/PlanningPractice
```

Откройте Codex в проекте и скажите **«В local/PlanningPractice перенеси срок задачи „Проверить восстановление базы“ проекта „Маяк“ на 27 ноября 2026 года и покажи дату в обоих планах»**. Если хотите сначала посмотреть последствия, попросите **«Покажи, что изменится»**. Предпросмотр читает текущую дату и перечисляет затронутые планы. При переносе срок и запись истории сохраняются вместе в карточке задачи.

В `Tasks/` лежит одна Markdown-карточка каждой задачи. В `Plans/` хранятся упорядоченные ссылки с ID. В Obsidian можно открыть карточку задачи из любого её плана. В Codex команда `plan-show ID` показывает актуальные даты активного плана или сохранённые даты закрытого цикла. Команды `task-list`, `plan-list` и `task-history` помогают найти запись и проверить изменение. В учебном хранилище тот же сценарий доступен для подготовки к поездке и кедровых проб. [Навык планирования](.agents/skills/brain-plan/SKILL.md) · [Генератор трёх примеров](examples/planning_vault.py)

## Открыть Гант

Для первого запуска создайте учебное хранилище командой `python3 examples/gantt_vault.py local/GanttLab`. Затем запустите `python3 -m second_brain --vault local/GanttLab work --port 8768`.

В рабочей админке выберите **Планы**, затем нужный план. В настольном Obsidian откройте команду **Открыть Гант**. Обе вкладки работают с одной карточкой задачи. Выберите строку, чтобы посмотреть согласованный срок, текущий прогноз и факт завершения, проверить основания или исправить сводку. В меню «Изменить даты» можно перенести прогноз отдельно от согласованного срока. В Codex попросите **«Разбери ручные правки Ганта в local/GanttLab»**.

Чтобы увидеть последствия переноса, выберите «Проверить восстановление базы» и нажмите **Что если…**. Введите предполагаемую дату завершения. В расчёте появятся проверка, зависимая веха «Готовность к переключению» и запас дней до согласованной даты каждой из них. То же можно спросить в Codex фразой **«В GanttLab что изменится, если проверку восстановления базы закончим 2 декабря 2026 года?»**. Прогнозы попадают в карточки после подтверждения. [Вехи и зависимости](docs/gantt.md#вехи-и-зависимости)

В списке планов откройте «План недели» и нажмите **Закрыть цикл…**. После подтверждения попросите Codex создать «План следующей недели» и включить в него существующую задачу «Проверить восстановление базы». Если изменить прогноз в новом плане, в закрытом Ганте останется дата на момент закрытия. [Как закрыть цикл](docs/gantt.md#закрытие-цикла)

[Учебные планы трёх направлений](http://127.0.0.1:8768/#plans) · [Что попробовать на «Маяке»](docs/gantt.md#учебный-маршрут) · [Плагин Obsidian](plugins/obsidian-gantt/README.md)

## Недельный обзор

В Codex попросите **«В GanttLab собери обзор за 16–22 ноября по закрытому “Плану недели”. Сохрани его со ссылками на Гант и записи»**. В Obsidian выпуск появится в `Reports/`. Его также можно открыть по названию в шапке закрытого Ганта.

В разделе «События недели» каждое утверждение ведёт к датированной записи или к подтверждённому завершению. Раздел «На момент закрытия» показывает, что было известно о работах, когда закрыли план. Ссылка «Гант» выделяет исходную строку, «Источник» открывает подтверждающий фрагмент. Рядом есть ссылки на Markdown для чтения в Obsidian. Название и группировку следующих выпусков можно задать в `Settings/Formats/Weekly.md`. [Навык и команды](.agents/skills/brain-weekly-review/SKILL.md)

## Цели и ключевые результаты

OKR подключается по потребности. Владелец выбирает направление, формулирует цель, называет измеримый ключевой результат и единицу измерения. Можно указать ориентир и связать результат с задачами, которые уже ведутся в планах. Карточка результата в `Plans/OKR/` хранит замеры с датами и источниками. До первого замера фактическое значение пусто.

Если папки `local/OKRLab` ещё нет, создайте учебное хранилище командой `python3 examples/okr_vault.py local/OKRLab`. В Obsidian откройте его `Home.md`. Для браузерного сценария запустите оболочку из папки программы.

```sh
python3 -m second_brain --vault local/OKRLab work --port 8770
```

В разделе **Планы → Цели и ключевые результаты** откройте «Время восстановления базы». В учебном протоколе «Маяка» за 22 ноября записаны 18 минут при ориентире 15 минут. Из результата можно открыть строку протокола и проверить одну задачу в «Запуске Маяка» и «Плане недели». Рядом есть ещё два примера с другими единицами измерения. [Открыть результаты](http://127.0.0.1:8770/#okr)

В Codex спросите **«В local/OKRLab какое время восстановления базы у Маяка? Покажи замер, ориентир и строку протокола»**. Для самостоятельного опыта на чистой копии выполните `python3 examples/okr_vault.py local/OKRPractice`. [Команды записи и чтения](.agents/skills/brain-plan/references/okr.md) · [Генератор примеров](examples/okr_vault.py)

## Добавить материал во входящие

Откройте вкладку **Входящие**. Вставьте текст, при желании укажите название и нажмите **Сохранить текст**. Для документов и изображений нажмите **Выбрать файлы** или перетащите их в форму. Скриншот переписки можно вставить прямо на вкладке сочетанием ⌘V или Ctrl+V. После сохранения вы увидите точный путь в своём хранилище. [Открыть входящие](http://127.0.0.1:8766/#inbox)

Текст сохраняется в Markdown, файлы — в исходном виде. При совпадении имён новая копия получает номер. Оболочка принимает до 1 МиБ вставленного текста и до 32 МиБ на файл. Материалы остаются в очереди до команды «Разбери всё новое» в Codex. В чате также можно поручить само сохранение. Для этого есть команды `inbox-text` (текст из stdin, необязательный `--title`) и `inbox-file "путь к файлу"`.

## Разобрать встречу и открыть карточку человека

В WorkshopVault Дарья Миронова отвечает за цветопробу в «Городской типографии» и ведёт запись звукового маршрута в «Полевых записях». Откройте её карточку и сравните две роли со строками 5 и 6 одной встречи. [Люди](http://127.0.0.1:8766/#people) · [Учебный протокол](examples/meeting.md)

Во входящих встреча уже обработана. Для самостоятельной пробы откройте «Сверка перед выездом.md», выберите существующую карточку Дарьи и направление «Полевые записи». Сохраните как общий факт дословный фрагмент строки 5 о месте записи. В карточке можно уточнить формулировку и посмотреть историю. Источник ведёт к первоначальной цитате. [Входящие](http://127.0.0.1:8766/#inbox)

Те же данные доступны из Codex. Примеры команд запускаются из корня программы.

```sh
python3 -m second_brain --vault local/WorkshopVault inbox
python3 -m second_brain --vault local/WorkshopVault inbox-read "Inbox/Сверка перед выездом.md" --start 5 --limit 1
python3 -m second_brain --vault local/WorkshopVault people --match "Дарья Миронова"
```

Для подтверждения используйте `inbox-process` с прочитанной ревизией, ID человека и выбранными строками. Команда `person ID --history` показывает историю формулировок, `evidence ID FACT_ID` — исходную цитату, `person-correct` сохраняет уточнение по ревизии. [Пример разбора](.agents/skills/brain-intake/SKILL.md) · [Команды для карточки человека](.agents/skills/brain-person/SKILL.md)

При разборе текстовой встречи точная копия попадает в `Sources/Originals`, ссылки на подтверждённые строки и карточки — в `Sources/Processed`. Входящий файл сохраняется и помечается как обработанный по содержимому. Повтор распознаёт тот же материал после переименования.

В рабочем контексте карточка показывает общие факты. Личные наблюдения открываются по явному выбору в карточке человека или через `person ID --personal`. Общая ссылка показывает только разрешённую цитату, даже если на той же строке есть личная подробность. При разборе владелец может отдельно открыть полный оригинал. Это режимы чтения внутри локального хранилища одного владельца, у которого есть доступ к файлам в Obsidian.

## Я и моя команда

Откройте **Люди → Команды**, создайте группу и добавьте участников из справочника. Карточку нового человека можно создать прямо в разделе «Люди». Один человек может входить в несколько групп. Из его карточки доступны все эти группы, из карточки команды — её участники.

В блоке **Я и моя команда** выберите свою карточку и команду, которую имеете в виду, когда говорите «моя команда». Каждый выбор можно изменить или снять отдельно. История смены состава хранится в карточке группы, история выбора владельца и команды — в `Settings/Owner.md`. [Открыть людей](http://127.0.0.1:8770/#people)

В Codex можно спросить **«К кому из моей команды обратиться по проверке переключения Маяка и почему?»**. Codex получает состав из выбранного хранилища, а ответственность сверяет с записью о роли или договорённости. Ответ может ссылаться и на строку состава, и на слова из встречи. Для самостоятельной проверки на вымышленных участниках создайте учебную копию командой `python3 examples/inbox_vault.py local/PeoplePractice --teams` и укажите её в вопросе. [Команды для людей и групп](.agents/skills/brain-person/references/teams.md)

## Разобрать всё новое

В чате Codex с выбранным хранилищем напишите **«Разбери всё новое»**. Если в рабочей папке несколько хранилищ, назовите нужное, например «Разбери всё новое в local/InboxLab». Очередь охватывает `Inbox/` и его подпапки. Markdown и TXT в UTF-8 читаются построчно. Для читаемого скриншота Codex может сохранить расшифровку и разобрать её по тем же правилам. Из расшифровки можно открыть исходное вложение. Если содержимое недоступно или требует пояснения, у владельца появится вопрос.

Для каждого направления владелец задаёт, как распознать его материалы, какие поля проектов можно менять и куда записывать факты о людях. Эти правила доступны в **Входящие → Правила направлений** и хранятся в Markdown в `Settings/Intake/`. Если подходящего правила или однозначной карточки нет, фрагмент остаётся в **Вопросах владельцу**. [Входящие](http://127.0.0.1:8766/#inbox)

У подтверждённого изменения есть карточка и строка неизменённого оригинала. Вопрос владельцу тоже привязан к конкретной строке. Ответьте на него в оболочке или попросите Codex передать уточнение, затем снова скажите «Разбери всё новое». Ранее подтверждённые части документа сохранятся. Тот же материал после переименования распознаётся по содержимому.

Для самостоятельной пробы можно создать отдельное хранилище с тремя настроенными направлениями. Четыре новых файла проверяют два ИТ-проекта, личную договорённость, парфюмерную серию и срок без названия проекта. Генератор требует свободный путь. [Учебное наполнение](examples/inbox_vault.py)

```sh
python3 examples/inbox_vault.py local/InboxPractice
python3 -m second_brain --vault local/InboxPractice work --port 8768
```

В Codex укажите `local/InboxPractice` и запустите разбор. Посмотрите результат в [обзоре](http://127.0.0.1:8768/#overview), [карточках людей](http://127.0.0.1:8768/#people) и [вопросах владельцу](http://127.0.0.1:8768/#inbox?view=triage). В учебном примере можно ответить, что срок относится к «Маяку», и посмотреть, как после второго обхода изменится срок этого проекта.

## Пройти деморежим

Откройте [локальный путеводитель](http://127.0.0.1:8765/). Для запуска или после перезагрузки компьютера выполните из корня проекта:

```sh
python3 -m second_brain --vault local/DemoVault demo
```

При первом запуске создаётся отдельное хранилище с тремя примерами. Нажмите «Начать знакомство» или выберите любую карточку. Выберите вопрос, прочитайте ответ и нажмите «Открыть источник». Путеводитель перечитает файл и выделит нужную строку. Чтобы пройти направление, откройте источники всех его вопросов.

На главной есть поле [«Спросить по записям»](http://127.0.0.1:8765/#ask). Введите, например, «Что мы решили по Маяку и Орбите?». Поиск охватывает проекты и заметки трёх демонстрационных направлений. В ответе у каждого проекта своя выдержка из Markdown и ссылка с номером строки. Нажатие раскрывает фрагмент прямо под ответом. Эту же ссылку можно скопировать или открыть в отдельной вкладке, чтобы прочитать запись целиком. Свободные вопросы доступны и со страницы каждого примера.

В конце нажмите «Добавить своё направление», введите название темы, заголовок заметки и факт. Задайте вопрос по своей заметке. Записи сохраняются в `local/DemoVault/Directions` и `local/DemoVault/Notes` и доступны в «Моих направлениях» после перезапуска. Отметки о просмотре сохраняются в этом браузере. Для работы путеводителя достаточно локальных файлов и поиска, учётная запись ИИ не требуется.

## Попробовать через команды

Команды запускаются из корня проекта. Нужны Python 3.9+ и SQLite с FTS5. На этом этапе используется стандартная библиотека Python.

```sh
python3 -m second_brain --vault "local/My Examples" examples
python3 -m second_brain --vault "local/My Examples" search "Что проверяет команда Маяка перед переключением?"
```

Откройте `Home.md` созданного хранилища для перехода ко всем трём направлениям. В выдаче команды `search` есть путь и номера строк. Для этого примера исходную строку можно прочитать так:

```sh
python3 -m second_brain --vault "local/My Examples" read "Projects/Переезд базы заказов.md" 11 11
```

В новом чате с ИИ, который умеет выполнять локальные команды, укажите папку проекта и путь к созданному хранилищу. Например:

> В этом проекте пользуйся командой `python3 -m second_brain --vault "local/My Examples"`. Какой вход согласован для первого запуска Орбиты? Найди запись через `search`, проверь фрагмент через `read` и укажи файл и строки. Если запрошенного факта в источнике нет, скажи об этом.

Затем можно спросить, где лежит запасной ключ, или что осталось у Кедра через сутки. В последнем случае важно сверить время наблюдения с вопросом. Для новой чистой копии примеров выберите другой путь. Команда `examples` создаёт только новое хранилище.

## Добавить свою тему

В хранилище примеров или в своей пустой папке доступны те же операции. Для своей папки из корня проекта выполните:

```sh
python3 -m second_brain --vault "local/My Vault" init
python3 -m second_brain --vault "local/My Vault" create direction "Астрономия"
```

Скопируйте значение `id` созданного направления вместо `ID_НАПРАВЛЕНИЯ`:

```sh
python3 -m second_brain --vault "local/My Vault" create note "Первое наблюдение" --direction ID_НАПРАВЛЕНИЯ --body "Взял лунный фильтр."
python3 -m second_brain --vault "local/My Vault" search "Какой фильтр я взял?"
```

Для проекта укажите тип `project`. Для другого знакомого названия добавьте `--alias`. Команда `list --direction ID_НАПРАВЛЕНИЯ` выводит записи одного направления. Свободную заметку можно создать без направления. ИИ может выполнить эти же шаги по просьбе «Заведи направление про астрономию и запиши моё первое наблюдение».

Файлы можно редактировать вручную. Для изменения через команды сначала используйте `show ID`, затем `update ID --revision ВЕРСИЯ --body "Новый полный текст"`. Изменение требует прочитанной версии и сохраняет поля шапки. Поиск охватывает карточки с ID в `Directions`, `Notes` и `Projects`. Индекс лежит в `.second-brain/` внутри хранилища и восстанавливается командой `rebuild`.

## Папки пользовательского хранилища
