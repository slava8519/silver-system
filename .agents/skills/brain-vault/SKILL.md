Из корня программы используй `python3 -m second_brain --vault "$VAULT"`, где `VAULT` — абсолютный путь выбранного хранилища. Выбирай команду по задаче.

| Задача | Команда и результат |
|---|---|
| «Проверь второй мозг» | `check --snapshot new` проверит карточки, правила направлений, квитанции и оригиналы. [Как прочитать замечания](#проверить-хранилище) |
| «Обнови все сводки и истории» | `refresh-all` за один вызов сверит карточки выбранного ваулта и вернёт счётчики по типам. [Как прочитать результат](#обнови-все-сводки-и-истории) |
| Архивировать историю проектов | Составь [предпросмотр по кварталам](../brain-record/SKILL.md#квартальный-архив-проекта) для запрошенных проектов и примени согласованный перенос. |
| Начать с пустого хранилища | `init` создаст папки и стартовые страницы. |
| Открыть админку | `work` откроет локальный сервер выбранного хранилища на порту 8766. Передай владельцу адрес из вывода. |
| Пройти три истории | `demo` создаст путеводитель на новом отдельном пути или продолжит существующий деморежим. Порт по умолчанию 8765. |
| Получить только три примера в Markdown | `examples` создаст их в новом каталоге. |
| Убрать демоданные и работать в этой папке | `demo-cleanup` покажет число учебных файлов для архива (`removeCount`), число сохраняемых учебных файлов (`keepCount`) и ревизию. Для согласованного переноса используй `demo-cleanup --apply РЕВИЗИЯ`. |
| Восстановить поисковый индекс | `rebuild` пересоберёт кеш из Markdown. Обычный поиск сам обновляет записи добавленных, изменённых и перемещённых файлов и убирает удалённые. |

В настольном Obsidian значок **Второй мозг** запускает рабочую оболочку этого хранилища по требованию. **Открыть в браузере** ведёт в текущий раздел. **Остановить админку** во вкладке или палитре команд выключает этот экземпляр. При выключенной админке для вопросов и правок используй обычные команды CLI. Инструкция по подключению плагина лежит в `.runtime/plugins/obsidian-gantt/README.md` установленного хранилища или в `plugins/obsidian-gantt/README.md` дерева исходников.

Для учебной проверки именно рабочей оболочки выполни из корня программы `python3 examples/working_vault.py "$NEW_VAULT"` с новым путём. Затем запусти `work` для созданного каталога. Состав можно проверить через `overview --brief`.

Для вопроса «что уберётся?» достаточно предпросмотра. При конфликте прочитай новый предпросмотр и сверь изменившийся состав с владельцем. После перехода проверь `cleaned`, сообщи `removeCount` и `keepCount`. Если `archive` содержит путь, укажи его. Рабочий обзор открывает ту же папку с собственными записями владельца. Если `available` и `cleaned` равны `false`, учебный набор не распознан.

Для пробы «разбери всё новое» используй `python3 examples/inbox_vault.py "$NEW_VAULT"`. Генератор подготовит три правила направлений, проекты, существующего участника и четыре новых файла для разбора.

Для проверки общих сроков в двух планах используй `python3 examples/planning_vault.py "$NEW_VAULT"`. В нём есть три направления, задачи с проектами и без проекта, планы с общими задачами.

Для просмотра «Коротко» и событий проекта создай учебную копию командой `python3 examples/gantt_vault.py "$NEW_VAULT" --project-updates`. В проекте «Маяк» три записи из Inbox. Его ID даёт `list --type project --match "Маяк" --limit 1`. После запуска `work` передай прямые ссылки на `/#record/ID` и `/#project-gantt/ID` по адресу этого хранилища.

## Проверить хранилище

Выполни `python3 -m second_brain --vault "$VAULT" check --snapshot new --limit 5`. Команда читает выбранное хранилище и сохраняет результат в пользовательском кеше. В рабочей оболочке та же операция доступна в **Обзор → Проверить хранилище**.

Приведи время завершения из `checkedAt`, статус, счётчики из `checked` и общее число замечаний из `issues.total`. При `issues` укажи путь, строку и причину первого замечания. При `line: 0` замечание относится к файлу или папке целиком. При `incomplete` часть данных прочитать не удалось. Следующую страницу прочитай командой `check --snapshot ID --limit 5 --offset 5`, подставив полученный `snapshot`. Все страницы с этим ID относятся к одному проходу. Если получено `snapshotWarning`, сообщи его и при необходимости запусти свежий проход с нужным смещением. Для проверки после исправлений используй `--snapshot new`. CLI возвращает 0 при `ok` и 1 при `issues` или `incomplete` с отчётом в stdout.

После переноса истории полный `check` сверяет файлы кварталов с контрольными суммами в проектах и проверяет служебные указатели для ссылок на кварталы. При `project.archive` сверяй файл и карточку проекта с состоянием до переноса. Чтобы проверить прежнюю цитату, открой сохранённый `source.href` или `report-source ID --index N` и сопоставь текст с исходным. [Архивирование проектов](../brain-record/SKILL.md#квартальный-архив-проекта)

После записи Inbox поле `check` в квитанции относится к указанному источнику. Для оценки всего хранилища используй команду `check`. Открытый вопрос владельцу допустим при исправных карточках и оригинале. [Обход входящих](../brain-intake/references/queue.md)

## Обнови все сводки и истории

Выполни `python3 -m second_brain --vault "$VAULT" refresh-all`. Достаточно одного вызова для всех направлений, проектов, людей и работ, включая вехи и задачи вне планов. Гант и открытые планы читают обновлённые карточки работ по ID. Правила направления определяют, какие проектные записи можно обновить. Закрытые планы, выпуски обзоров и ручные формулировки сохраняются.

При сверке уже записанных событий проход учитывает квартальные архивы проектов. Для проекта основаниями служат записанные поля состояния, подтверждения в теле карточки, завершённые разборы Inbox и решения из заметок с явной ссылкой на проект в той же строке. Для работы используются её собственные события, подтверждённое завершение и датированные замеры фактической готовности. У людей проход сверяет ручные правки общих фактов с предыдущей формулировкой и оригиналом.

Сообщи `changedCards` из `totalCards`, сколько добавлено событий, обновлено сводок и зафиксировано правок общих фактов о людях. В `cards` виден состав ваулта, в `details` — результат по каждому виду обновлений. Если есть `example`, по его ID сверь сохранённый результат и приведи ссылку на карточку. При `issues.total` укажи карточку и причину из `issues.items`. Дополнительные замечания доступны через `--offset N --limit 20`. Размер страницы влияет только на выдачу замечаний. Если владелец просит проверить повторный запуск, сравни счётчики и ревизии карточек.

Проход работает с уже записанными основаниями. Новые сообщения разбираются командой [«Разбери всё новое»](../brain-intake/SKILL.md). Для проверки конкретной записи открой [события проекта](../brain-record/SKILL.md#коротко-и-события-проекта), [строку Ганта](../brain-plan/references/gantt.md#сводка-и-правки) или [историю человека](../brain-person/SKILL.md).

Когда запрос охватывает сводки открытых планов, целей и КР, после общего прохода обработай их [построчно по источникам](../brain-plan/references/gantt.md#сводки-и-истории-строк-плана).

Если владелец также просит обновить проценты Ганта, отдельно [оцени готовность работ по источникам](../brain-plan/references/readiness-estimates.md). Оценки выбирает Codex по материалам работ.
