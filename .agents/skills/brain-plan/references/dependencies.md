# Вехи и сценарии плана

Работы связаны по ID во всём хранилище. Одна связь действует во всех планах, где встречаются её участники.

- Чтобы создать веху, вызови `task-create "название" --kind milestone --request-id КЛЮЧ` и включи её в выбранные планы через `plan-add ПЛАН ВЕХА`. Указывай `--due` только при известной договорённости. Проект и направление необязательны.
- Если Б зависит от завершения А, вызови `task-dependency Б --add А`. Для просмотра обеих сторон связи служит `task-dependency Б`, для снятия — `task-dependency Б --remove А`. Основание связи находится в `linkPath` на строке `linkLine`. Историю решений, авторов и даты покажет `task-dependency Б --history --limit 5`. При цикле покажи владельцу цепочку из сообщения об ошибке.
- На вопрос «Что изменится, если закончим к этой дате?» вызови `task-scenario А --forecast YYYY-MM-DD`. Покажи изменения прогнозов, затронутые планы и строки, где расчёту недостаёт данных. У каждой работы есть `path`. Отрицательный `slackDays` показывает опоздание к согласованной дате, положительный — запас в календарных днях. Факт завершения требует отдельного свидетельства.
- Веха может наступить в день завершения последнего предшественника. У зависимой задачи расчёт сохраняет календарный интервал между её началом и сроком. Более поздняя самостоятельная оценка задаёт нижнюю границу. Предпросмотр отвечает на гипотетический вопрос.
- Для запрошенной владельцем записи повтори тот же сценарий с `--apply REV` из расчёта. При конфликте покажи новый расчёт. Если `truncated` или `plansTruncated` равны true, прочитай следующие строки через `--offset` либо следующие планы через `--plans-offset`. Подтверждение относится ко всему рассчитанному сценарию.
- После записи сверь `id`, `due`, `forecast`, `completed` одной работы в затронутых планах через `plan-show ПЛАН --task РАБОТА`. Основание изменения прогноза хранится в `task-schedule РАБОТА --history`.
