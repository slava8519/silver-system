# Как прикинуть готовность работы

На вопрос «сколько сейчас?» покажи сохранённое значение, дату и основание через `gantt-row ID --limit 3`. На просьбу «прикинь» верни предложение. Просьба «обнови проценты» или «актуализируй Гант» включает запись обоснованных изменений в карточки работ.

## Найти, что изменилось

Если владелец хочет проверить эффект разбора входящих на OKR, перед обновлением прочитай `okr-progress ПЛАН` и сохрани значения и даты работ из `plan-readiness` по всем страницам. После обновления повтори обе команды и сравни строки по ID. Для уже выполненного разбора возьми состояние до него из доступной резервной копии или истории. Отдельно укажи число изменившихся процентов и их вклад в итог по весам. Даты правок сводки и даты замеров в истории готовности могут различаться. Гант показывает целые проценты, а команды возвращают значения для точного сравнения.

- Для обзора активного плана начни с `plan-readiness ПЛАН --review-on ГГГГ-ММ-ДД --limit 20`. Подставь дату сверки. Продолжай с `--offset`, равным `nextOffset`, до значения null. Сверь число уникальных ID с `planTotal`. В состав входят прямые работы и работы, включённые через КР. Значение null означает неизвестную готовность. Ноль, факт, оценка, дата и автор показаны отдельно. Путь основания — `sourcePaths[source.pathIndex]`, строка — `source.line`. Для заметки или проекта выполни `read ПУТЬ N N`, для оригинала Inbox — `original ID --start N --limit 1`. ID оригинала — имя файла без расширения. `cardLine` указывает строку в самой задаче. Для закрытого плана опусти дату сверки, используй `snapshotPath` и `snapshotLine` для ссылки на сохранённое состояние. В снимке координаты первичных источников относятся к моменту закрытия.
- Если нужен только список для сверки, добавь `--candidates`. Выдача показывает число отобранных работ в `total` и полный размер плана в `planTotal`. В `reviewFlags` входят неизвестный процент (`unknownValue`), отсутствующая карточка или недоступный источник оценки (`missingTask`, `unavailableSource`), незавершённая работа с прогнозом раньше выбранного дня (`pastForecast`), записанный ноль через семь календарных дней от старта (`zeroAfterWeek`). `laterCitedEvent` означает, что в карточке есть датированное событие со ссылкой позднее даты оценки. Доступность цитаты этого события проверь при чтении подробностей. `firstGanttReview` означает первую сверку, `unreviewedGantt` — расхождение с сохранённой отметкой сверки дат, зависимостей и ручных записей Ганта. Само расхождение не указывает автора изменения. Дата сверки применяется к прогнозу и возрасту старта. Проценты и события относятся к текущим записям.
- При актуализации квартала отдельно проверь новые протоколы, разборы Inbox и события его проектов за запрошенный период. Отбери также строки, к которым эти свидетельства относятся по результату, проекту, исполнителю или альтернативному названию, включая работы без `reviewFlags`. Для отдельного проекта используй `project-gantt ID --limit 10`. Список признаков охватывает сведения, уже записанные в карточках работ и их текущих основаниях. Дата события и момент редактирования Markdown — разные сведения.
- Только для отобранных строк открой нужные детали. `task-readiness ID --limit 3` даёт историю процентов и оснований, `gantt-row ID --limit 3` — ручные решения, последние события и цитаты. Для проверки нового протокола или события проекта прочитай первичный источник, при необходимости вызови `project-updates ПРОЕКТ --limit 3`. При расхождении назови источники и даты. Для вехи проверь наступление события. Более старое событие не обосновывает изменение текущей готовности.

## Выбрать процент

1. Если источник прямо называет процент **готовности этой работы**, возьми его как факт. Для счётной работы с равнозначными единицами посчитай `100 × готово / требуется`. Проверь, что знаменатель охватывает всю работу. Например, «приняты 3 из 4 образцов» даёт 75%, если получение четырёх принятых образцов и есть результат. Доля успешных проверок, целевое значение КР и доля истекшего времени сами по себе готовность работы не определяют.
2. При качественном свидетельстве используй согласованную шкалу направления, если она есть. Иначе подбери ближайший подтверждённый этап по ориентирам ниже. В основании укажи, что уже сделано и какой результат ещё предстоит получить.

   | Оценка | Основание |
   | --- | --- |
   | 0% | Подтверждено, что к работе ещё не приступали. |
   | 10% | Начат разбор или сделана первая попытка. |
   | 30% | Есть первый промежуточный результат. |
   | 50% | Сделано около половины, либо исполнитель подтвердил ход работы и назвал срок оставшейся части. |
   | 70% | Основная часть готова, идёт пилот или остались конкретные проверки и доделки. |
   | 90% | Результат готов к приёмке или используется, осталось финальное подтверждение или выпуск. |

3. Для 100% проверь подтверждение результата по всей работе и открытые подзадачи. Если источник прямо подтверждает приёмку всей работы, но не называет процент или счётчик, укажи 100% как вывод ИИ (`estimate`) и приведи цитату о приёмке. При снятии потребности укажи отдельно, кто и когда принял решение, и проверь, как владелец учитывает такое закрытие. Процент, дата завершения и достижение КР имеют отдельные основания. Для записи даты используй [сроки и завершение](schedule.md).
4. Если сведений не хватило, сохрани прежнее значение, в том числе пустое. В ответе перечисли такие строки с пометкой «без фактов» и укажи, что требуется подтвердить. Если по правилам направления отсутствие свидетельства о старте означает ≈0%, проверь прежнюю историю работы. При обновлении прежде пустой строки можно записать 0 как `estimate` со ссылкой на датированное состояние проекта, причиной «без фактов о начале» и вынести строку на подтверждение владельцу. Если подходящего источника нет, оставь строку открытой для уточнения.

## Записать и проверить

Для датированной оценки по этапу возьми свежую `revision` из `task-readiness` и выполни команду с префиксом CLI выбранного vault.

```sh
task-readiness "$TASK" --value 70 --kind estimate --actor ai --date "$EVENT_DATE" \
  --source "$SOURCE_PATH" --line "$LINE" --quote "$QUOTE" --revision "$REVISION" \
  --reason "Пилот запущен, осталась проверка на втором участке."
```

Цитируй точную строку Markdown-карточки в `Notes/` или `Projects/`, либо сохранённого текстового оригинала Inbox по пути из квитанции разбора. Для прямо указанного процента используй `--kind fact`. Для подтверждённой доли «3 из 4» в той же команде передай `--kind fact --count 3 4 --value 75` и процитируй оба числа. Для периодической дроби округли долю до сотых процента. Если округление даёт 0% или 100% при положительной незавершённой доле, сохрани больше знаков.

Если новые сведения расходятся с ручной или подтверждённой владельцем записью, покажи прежнее значение и предложенное изменение с источником. Передавай `--owner-confirmed` только по явному решению владельца о конкретном значении. Для замены записанного факта приблизительной оценкой также требуется его решение. При конфликте ревизии перечитай карточку. Повтор уже учтённого свидетельства пропусти.

После записи перечитай `gantt-row ID --limit 1` и проверь процент, тип, дату и открываемую цитату. Для итогов КР, цели и плана используй [расчёт по весам](okr-progress.md). В ответе покажи прежний и новый процент, отметь оценку знаком ≈, приведи основание и перечисли оставшиеся вопросы.
