# Критерии, готовность и дерево плана

Найди ID плана, цели и КР через `plan-list` и `okr-plan ПЛАН --view results --limit 5`. Команды записи используют актуальную ревизию изменяемой карточки. После конфликта перечитай её. Для ответа об историческом квартале используй `okr-plan`, `okr-progress` и `plan-tree` закрытого плана. `okr-show` читает сегодняшнюю карточку.

## Достигнут ли результат

1. Прочитай `okr-show КР --criteria --limit 5`. Для одного условия используй `okr-criterion-show КР КРИТЕРИЙ`. Сверь исходное значение, направление сравнения, порог, последний замер и источник. У подтверждения да/нет укажи цитату. Если данных для вывода не хватает, назови конкретное условие.
2. Чтобы привязать порог к основной метрике, вызови `okr-criterion-add КР "Доля пропусков" --kind numeric --primary --operator '<=' --target 5 --request-id КЛЮЧ --revision РЕВ`. Для отдельного числового показателя укажи `--unit` и его единицу. Для дополнительного условия используй `okr-criterion-add КР "Склад участвует в прогоне" --kind boolean --request-id ДРУГОЙ_КЛЮЧ --revision РЕВ`. КР, состоящий из качественных условий, можно создать без единицы измерения.
3. Запиши наблюдение через `okr-criterion-measure КР КРИТЕРИЙ --value 4 --date YYYY-MM-DD --source "Notes/Протокол.md" --line N --quote "точная цитата" --revision РЕВ`. Для исходного замера добавь `--baseline`; для качественного условия передай `--value true` или `--value false`. Можно указать базу при создании через `--baseline`, `--baseline-date`, `--baseline-source` и `--baseline-line`. Ссылку на конкретную строку и её цитату проверь перед записью.
4. Для нового согласованного порога выполни `okr-criterion-target КР КРИТЕРИЙ --operator '>=' --target 6 --revision РЕВ`. История доступна через `okr-criterion-show КР КРИТЕРИЙ --history targets --limit 5`; для истории фактов или исходных замеров используй `measurements` или `baselines`. Для последующих страниц передавай `--offset`.

## Как рассчитана готовность

- Для веса результата в цели выполни `okr-weight КР --value 0.3 --revision РЕВ_КР`. Для веса конкретной работы в результате добавь `--task ЗАДАЧА`. При снятии значения передай `--clear`. Храни указанные владельцем доли в диапазоне 0…1. Явный ноль исключает вклад. Пропущенный вес требует уточнения.
- Состояние и историю работы читай через `task-readiness ЗАДАЧА --limit 3`. Для оценки по источнику выполни `task-readiness ЗАДАЧА --value 70 --kind estimate --date YYYY-MM-DD --actor ai --reason "почему такая оценка" --source "Notes/Сводка.md" --line N --revision РЕВ_ЗАДАЧИ`. Для подтверждённого процента передай `--kind fact`. Если владелец прямо сообщил или исправил готовность, укажи его решение и `--owner-confirmed`. Дату завершения записывай отдельно при наличии основания.
- Выбери нужный уровень командой `okr-progress ПЛАН --result КР --limit 5`, `okr-progress ПЛАН --objective ЦЕЛЬ --limit 5` или `okr-progress ПЛАН --limit 5`. В поле `contribution` у работы или КР показан его вклад в процентных пунктах. Для итога нужны сумма весов 1 и готовность каждого участника с положительным весом. Среднее за период доступно, когда рассчитаны все его цели. В ответе укажи, какие веса или значения отсутствуют и какие значения являются оценками.

## Как связаны строки

- Прочитай `plan-tree ПЛАН --result КР --limit 10` для одной ветви или опусти `--result` для всего плана. Поля `id`, `key`, `parentKey` и `level` дают карточку, место в ветви и вложенность. Если спрашивают о сроке вложенной вехи, найди её здесь и прочитай `task-schedule ID`. В списке взвешенных инициатив показаны только прямые связи с КР. Один ID работы может фигурировать в нескольких ветвях. Для подсчёта уникальных работ используй `okr-plan ПЛАН --view tasks`.
- Вложенность относится к выбранному плану. Убедись, что обе работы входят в него. Выполни `plan-parent ПЛАН РАБОТА --parent РОДИТЕЛЬ --revision РЕВ_ПЛАНА` или `--clear`, чтобы вернуть работу на верхний уровень её ветви. Сверь результат через `plan-tree`. Для календарной зависимости используй [команды зависимостей](dependencies.md).
- Для проекта, где есть источники по КР, используй `okr-context КР ПРОЕКТ --add --revision РЕВ_КР`. Удали связь через `--remove`, проверь `okr-show КР --projects --limit 5`. Для снятия участия работы в результате выполни `okr-unlink КР ЗАДАЧА --revision РЕВ_КР`. Затем сравни состав КР и плана. Работа может входить в этот план также по прямой ссылке или через другой КР.

Если владелец передал таблицу для обновления, читай заголовки, единицы, лист и координаты ячеек. Сопоставляй работы по устойчивым ID и контексту периода. Для проверяемого замера сохрани в заметке точную выписку с датой, именем файла, листом и адресом ячейки. Записывай изменения в карточки теми же командами. Пустые ячейки, оценки и измеренный факт имеют разный смысл.
