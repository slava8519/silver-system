# Сводки строк Ганта и правки владельца

Если нужно сравнить прогноз с исходным расписанием, прочитай `gantt-row ID`. При наличии поля `baseline` ответ содержит базовую дату плана и номер её строки `baselineLine`. Для договорённости о сроке используй `due`.

Для процента на полосе работы прочитай `gantt-row ID`. Поле `readiness` содержит последнее датированное значение, тип (`fact` или `estimate`) и основание. При `null` процент неизвестен, при значении `"0"` записан ноль. Подтверждённую дату завершения смотри в `completed`. В закрытом периоде используй Гант этого плана и показания его снимка. [Прикинуть готовность по источникам](readiness-estimates.md) · [Проверить веса и расчёт целей](okr-progress.md)

Используй тот же префикс CLI и выбранный vault, что в основном навыке.

По просьбе открыть Гант запусти рабочую оболочку для выбранного хранилища командой `work --port ПОРТ` или используй уже запущенную для него. Каталог открывается по `/#activity`, Гант выбранного проекта по `/#project-gantt/ID_ПРОЕКТА`, Гант плана по `/#plan/ID_ПЛАНА`. В настольном Obsidian тот же редактор открывает команда «Открыть Гант». [Плагин](../../../../plugins/obsidian-gantt/README.md)

В Ганте OKR общий вид открывается до КР. Ссылка `/#plan/ID_ПЛАНА?task=ID_ЗАДАЧИ` раскрывает ветку и показывает карточку в закреплённой нижней панели. В интерфейсе разделу «Последнее» соответствует «История». На шкале по умолчанию видны полосы и линия текущей даты. Чтобы увидеть прогноз, согласованный срок или зависимости на шкале, включи нужные пометки в меню **Вид**. Выбор сохраняется локально.

## Сводки и истории строк плана

План, цель, КР и группа работ имеют собственные «Коротко» и историю. В Ганте нажми название строки. Стрелка рядом управляет раскрытием ветки. Ссылка на цель имеет вид `/#plan/ПЛАН?row=objective/ЦЕЛЬ`, на КР — `/#plan/ПЛАН?row=result/КР`.

1. Для запроса «обнови сводки и историю всех целей и КР» найди период через `plan-list`. Прочитай `okr-plan ПЛАН --view objectives --limit 5`, затем `okr-plan ПЛАН --view results --objective ЦЕЛЬ --limit 5`. При `truncated` дочитай следующие страницы через `--offset`. Для отдельной строки достаточно её ID и плана.
2. Прочитай `gantt-row ID --plan ПЛАН --kind ВИД --limit 3`. Виды строк — `plan` (ID самого плана), `objective`, `key_result`, `group`. Для группы используй ключ `outside`, `project/ID` или `direction/ID` из выбранной группировки. Ответ содержит `revision`, текущую сводку `brief`, собственные события `latest` и их источники. Для прежних редакций добавь `--changes`, для событий работ в составе — `--work-events`. У последних указаны исходная задача и её карточка.
3. Сверь факты с первичными записями через `read "Notes/имя.md" N N`. Для вывода о достижении КР проверь `okr-show КР --criteria` и его замеры. Процент готовности работ характеризует выполнение работ. Для цели сформулируй общий результат по её КР, для КР — что подтверждено по его критериям, для периода — что изменилось в плане в целом. Указывай даты, риск и решение только при наличии основания для этого уровня.
4. «Коротко» начни с итога до 160 знаков. Добавь хотя бы одно подтверждённое поле в порядке **Сделано → Дальше → Мешает → Риск → Срок → Решение**. Используй каждое подходящее поле один раз, до 240 знаков текста на поле и до 700 знаков на всю сводку. Между полями ставь ` • `, например `Замер восстановления уложился в целевое время. • Сделано: протокол принят • Дальше: повторить замер на втором стенде`. Несколько пунктов внутри поля можно разделить точкой с запятой. Пустые поля опускай.
5. Передай в `gantt-edit` JSON через stdin. Для сводки нужны `kind`, `planId`, `id`, текущая `revision`, `field: "brief"`, `text` и `sources` с точными координатами и цитатами. Для отдельного нового факта сделай вторую запись с новой ревизией, `field: "latest"` и `date` в формате ГГГГ-ММ-ДД. Дату должен подтверждать источник. Если у события нет подтверждённой даты, явно передай `"date": null`. Изменяя прежнее событие, передай его `entryId`. По каждой строке сохраняй только новые сведения. Если ручная запись уже передаёт тот же факт, учти её и сохрани авторство.
6. Перечитай каждую изменённую строку. Проверь цитаты, дату, автора и то, что выбран нужный уровень. При `manual: true` действуй по правилам ручных правок ниже. В очереди `gantt-feedback` для сводной строки бери её `id`, `kind` и `planId`, чтобы прочитать `gantt-row ID --kind ВИД --plan ПЛАН --manual`. В ответе владельцу укажи, какие строки удалось обновить и по каким не хватило новых оснований. Закрытый период читай по его снимку.

## Проект и его планы

Для «Коротко» и истории всего проекта используй [карточку проекта](../../brain-record/SKILL.md#коротко-и-события-проекта). Эти же данные видны над работами в Ганте проекта. Для резюме одной работы используй `gantt-row`.

- Найди проект через `activity-list --view projects --match "мастерская" --limit 3`. Прочитай `project-gantt ID_ПРОЕКТА --limit 5`. В выборку входят его задачи и вехи из всех периодов, включая работы без дат и без плана. Согласованное начало и срок из карточки проекта читай отдельно от дат работ. Для подробностей по источнику, прогнозу и зависимостям работы используй `gantt-row`, `task-schedule` и `task-dependency`.
- Для сопоставления с кварталом выполни `activity-list --view plans --project ID_ПРОЕКТА --limit 5`. В `projectLink` указаны число работ проекта в конкретном плане, число его работ с прямой связью с КР и число КР, для которых проект указан как источник контекста. Состав закрытого периода относится к моменту закрытия. Чтобы получить названия инициатив по КР, используй `okr-plan ID_ПЛАНА --view tasks --result ID_КР`.
- Новая работа всего проекта создаётся через `task-create "название" --project ID_ПРОЕКТА --request-id КЛЮЧ`. В конкретный план или КР добавляй её по просьбе владельца. Начало и срок самого проекта меняются в его [канонической карточке](../../brain-record/SKILL.md).
- Для «берём проект в план» найди план через `plan-list --match "название" --limit 3` и проект через `activity-list --view projects --match "название" --limit 3`. Выполни `plan-project ПЛАН --include ПРОЕКТ --revision РЕВИЗИЯ_ПЛАНА`. Для «сними включение проекта» используй `--exclude ПРОЕКТ`. Проверь `activity-list --view plans --project ПРОЕКТ --plan ПЛАН --limit 1`. Флаг `projectLink.explicitlyIncluded` показывает решение владельца, включая проект с нулём работ. После снятия включения план может сохранять работы и контекст КР.
- На вопрос «какие проекты входят в этот план?» смотри `activity-list --view projects --plan ПЛАН --limit 5`. В `planLink` есть основание для каждого проекта. Если спрашивают только о явно выбранных, учитывай `explicitlyIncluded` и пройди следующие страницы при наличии продолжения.
- Для «возьми в план вот эту работу проекта» найди её через `task-list --project ПРОЕКТ --match "название" --limit 3`. У явно включённого проекта используй `plan-project ПЛАН --project ПРОЕКТ --task РАБОТА --revision РЕВИЗИЯ_ПЛАНА`. Когда владелец выбрал только задачу, а проект целиком ещё не включён, достаточно обычного `plan-add ПЛАН РАБОТА`. Проверь ID через `plan-show ПЛАН --task РАБОТА`. При конфликте перечитай план и сверь решение с более свежей правкой. В закрытом периоде читай снимок.

## Сводка и правки

1. Найди задачу через `task-list --match "название" --limit 3`. Прочитай `gantt-row ID --limit 3`. В ответе есть текущая ревизия, даты задачи, текст, автор и ссылки. Свежая правка из Obsidian уже видна здесь.
2. Для «Коротко» дай итог в одной фразе. Добавь следующий шаг или риск, когда он следует из записи. Для «Последнее» возьми конкретное событие. Найди основание через `search "фраза" --limit 3`, сверь нужную строку через `read "Notes/имя.md" N N`. Источником может быть также карточка проекта. Дата события — только из основания.
3. Передай в `gantt-edit` JSON через stdin. Обязательны `id`, `revision`, `field` (`brief` или `latest`), `text` и `sources` вида `[{"path":"Notes/имя.md","line":12,"quote":"точная цитата"}]`. Новому событию можно дать `date` в формате ГГГГ-ММ-ДД. Для исправления имеющегося события укажи его `entryId`. Бери новую ревизию из ответа каждой записи. Проверь итог через `gantt-row`.
4. При `manual:true` сохрани формулировку владельца. Если новые сведения меняют вывод, добавь отдельное подтверждённое событие и предложи владельцу новый текст в чате. Когда владелец явно одобрил именно этот текст, используй `gantt-edit --accept-manual REV` со сверенной версией ручной записи и источниками. При конфликте перечитай строку и сверь предложение с актуальной правкой. Перед добавлением проверь, учтён ли факт, в том числе в ручном исправлении.
5. По просьбе «разбери ручные правки плана» или «разбери правки Ганта» вызови `gantt-feedback --limit 5` либо добавь `--plan ID`. Для строки `kind=plan-projects` поле `id` указывает на план. Прочитай `plan-project ID --history --pending --limit 5` и все следующие страницы через `--offset`. Первыми приходят свежие решения. Для разбора восстанови хронологию от ранних к поздним и сверь проект и выбранные работы по ID с текущим составом. Для строки задачи прочитай `gantt-row ID --manual --limit 5`, при необходимости постранично. Сверь текущие даты и уточнения, в том числе удалённые записи. При первой сверке даты задают исходное состояние. Записывай в другую карточку только явно подтверждённое изменение нужной сущности. При сомнении вынеси вопрос владельцу и оставь запись на сверке.
   При изменении связей сверь текущих предшественников через `task-dependency ID` и недавние решения через `task-dependency ID --history --limit 3`.
6. По завершении разбора вызови `gantt-reviewed ID TOKEN` с токеном из очереди и снова запроси первую страницу. Для просьбы только показать правки достаточно чтения. В ответе укажи, что учтено и в какой карточке, со ссылкой на запись или её основание.
