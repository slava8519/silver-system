# Серия и её формат

Используй тот же префикс CLI с выбранным vault. Для разового выпуска достаточно шаблона. Серия объединяет выпуски одной редакционной линии. Выбери её по ID, даже если рядом есть отчёт с похожим названием.

```sh
python3 -m second_brain --vault "$VAULT" report-series-create "$SERIES_TITLE" \
  --template "$TEMPLATE" --cadence weekly --start 2026-11-16 --request-id "$REQUEST_ID"
python3 -m second_brain --vault "$VAULT" report-series-show "$SERIES_ID"
python3 -m second_brain --vault "$VAULT" report-list --series "$SERIES_ID" --limit 5
```

Дата начала задаёт первый день первого периода. Доступны `daily`, `weekly`, `biweekly`, `monthly`, `quarterly`, `yearly`. Очередной выпуск готовят по команде владельца. Календарь серии задаёт период для следующей подготовки.

## Готовить по расписанию

Для заданной владельцем периодической подготовки используй планировщик, доступный в клиенте. В поручении укажи путь к хранилищу и программе, ID серии, часовой пояс, время запуска и ожидаемый результат — черновик для просмотра или сохранённый выпуск. Перед запуском расписания сверь первый период с намерением владельца. Создание серии в vault само по себе задаёт только календарь периодов.

При запуске получи текущую локальную дату в заданном часовом поясе. Команда `report-series-list --due-on YYYY-MM-DD` возвращает серии, у которых последний день очередного периода наступил или прошёл. Если нужны только полностью прошедшие дни, передай вчерашнюю дату. Для одной серии удобнее `report-series-show ID` со сравнением `nextEnd` с той же границей. У подготовки к будущей встрече дату разговора укажи отдельно от периода фактуры.

Для каждого запрошенного периода пройди подготовку и приёмку выпуска. Используй ключ запроса из ID серии и дат. После сохранения перечитай серию или первую страницу списка: сохранённый период уже учтён. При запуске после перерыва обработай пропущенные периоды в разрешённом диапазоне. Если готовить нечего, заверши проверку. Если для периода недостаточно данных, укажи, чего именно не хватает, и заверши попытку. Это сохраняет возможность повторить её после появления записей.

## Создать или уточнить шаблон

Прочитай `report-template-show ID`. Для формата из примера выясни, какие требования владелец закрепил постоянно, а какие детали понадобились лишь в одном выпуске. Если дана действующая инструкция к формату, сохрани её обязательные рубрики, условия их появления, лексику, вложенность, правила чисел и порядок тем. Размести правила автора в `guidance`, читателей в `audience`, а заготовку для выпуска в `body`. Проверь, как текст будет выглядеть при вставке в целевой канал.

```sh
python3 -m second_brain --vault "$VAULT" report-template-save "$TITLE" \
  --audience "$AUDIENCE" --guidance "$GUIDANCE" --body-file "$SCAFFOLD_FILE"
```

Для обновления добавь `--id "$TEMPLATE" --revision "$REVISION"` из только что прочитанной карточки. Сохрани прежние правила, которых правка не касается. Если кто-то успел сохранить новую версию, перечитай её и перенеси согласованное изменение. Для сравнения двух редакций запроси каждую через `report-template-show ID --version N`. Ссылку старого выпуска на версию можно проверить через `report-show ID --brief`.

Правку одного текста учитывай в пределах этого выпуска. Если владелец изменил правило для будущих выпусков, сохрани новую версию шаблона. Если он исправил исходный факт, найди первоисточник и выполни согласованную правку через соответствующий навык карточки или планирования.
