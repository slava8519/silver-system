Из корня программы используй `python3 -m second_brain --vault "$VAULT"`, где `VAULT` — абсолютный путь выбранного хранилища.

Для просьбы [«Обнови все сводки и истории»](../brain-vault/SKILL.md#обнови-все-сводки-и-истории) используй общий проход по ваулту.

Найди карточку через `list --type project --match "название или алиас" --limit 3`. Подставь нужный тип. При совпадении имён различай записи по направлению и пути.

- Для новой карточки используй `create note "название" --body "текст" --request-id КЛЮЧ`. Выбери уникальный ключ создания. Повторяй ту же отправку с прежним ключом и полями. Типы `direction`, `project`, `note` означают постоянную область, работу с конечным результатом и заметку. Связь задаёт `--direction ID`, дополнительное имя — `--alias`.
- Для изменения возьми версию через `show ID --brief`. В `update ID --revision ВЕРСИЯ` передай только изменяемые поля, например `--status "значение"` или `--direction ID`. Для снятия срока используй `--clear-due`.
- Согласованное начало проекта задавай через `--project-start ГГГГ-ММ-ДД` при создании или изменении карточки. Для снятия используй `--clear-project-start`. В `show ID --brief` поле `projectStart` и его `fieldSources` указывают на решение владельца. У проекта без задач оно тоже может быть заполнено. Даты отдельных работ проверяй в их карточках.
- `--body` заменяет весь текст, `--alias` задаёт новый список имён. Чтобы дополнить текст или список имён, сохрани прежнее содержимое. При замене тела проекта сохрани ссылки на кварталы и служебные комментарии рядом с ними. Для тела или поля из `truncatedFields` открой целевую карточку через `show ID`. При конфликте перечитай её, сверь ручное изменение и запрошенную правку.

Верни путь сохранённой карточки. В админке владелец может открыть её в разделе **Карточки**, нажать **Редактировать** и сверить правку в **Предпросмотре**.

## Коротко и события проекта

Для выбранного проекта прочитай `project-updates ID --limit 3`. Вернутся текущая сводка, страница событий из карточки и её квартальных архивов, основания и ревизия Markdown. Для архивного события бери путь из `events[].path` и строку из `events[].line`. У события в самой карточке действует общий `path`. Старые записи «Журнала» и «Истории статусов» можно найти через `search "фраза" --history`. При `truncated` читай следующие события через `--offset`. Если у события нет даты, укажи это. Момент записи не доказывает дату события.

Когда владелец просит внести подтверждённый факт по заметке, проекту или сохранённому текстовому оригиналу, сверяй точную строку основания. Вызови `project-update ID --field event --revision REV --text "событие" --source "относительный путь" --line N --quote "точная цитата"`. Добавляй `--date YYYY-MM-DD`, когда цитата устанавливает дату события. Для вывода о текущем состоянии используй ту же операцию с `--field brief` и актуальной ревизией. Отличай новый факт от повторного сообщения о нём.

Если ручная формулировка расходится с новым фактом, сохрани подтверждённое событие и вынеси предложение владельцу. После явного принятия конкретного текста для прочитанной версии передай `--accept-manual REV` в ту же команду для сводки, с цитатой и `--revision REV`. В рабочей оболочке владелец также может изменить «Коротко» в карточке проекта. При конфликте ревизий перечитай запись и сверь правку. В конце проверь результат через `project-updates` и укажи источник. Для материала из Inbox используй [правила направления и пакетный разбор](../brain-intake/references/queue.md).

## Квартальный архив проекта

Для предпросмотра выполни `project-history-archive ID`. На определённую дату используй `--as-of YYYY-MM-DD`. Посмотри число записей в `moved`, число пропусков в `skippedLinks` и состав кварталов в `archives`. Программа проверяет датированные записи в разделах «Журнал», «История статусов» и «Последнее». Архивируются записи старше 60 дней. В каждом разделе остаются как минимум пять самых свежих датированных записей, если столько было, а также записи с неизвестной датой и записи, которые нельзя безопасно переместить.

Чтобы применить согласованный перенос, повтори команду с тем же ID, датой и `--apply РЕВИЗИЯ` из предпросмотра. При конфликте пересмотри обновлённый состав. Проверь `applied` и страницу исторических событий через `project-updates ID --limit 3 --offset N`. Для перенесённого фрагмента открой сохранённую ссылку на строку или основание отчёта и сверь путь, текст и дату. Квартальные Markdown-файлы читаются по ссылкам из карточки. Последующие уточнения сохраняй в рабочей карточке со ссылкой на источник. Обычная карточка в браузере открывает текущие поля, сводку и три события. **Полный текст и история** ведёт к полному Markdown и действию **Архивировать историю**. После переноса квартальные файлы доступны в карточке и через поиск `--history`.

Для разбора пропущенной записи сопоставь её текст с оригиналом и проверь точное место назначения спорной ссылки. Если источник установлен, передай файл JSON через `--reviewed-links ФАЙЛ` при предпросмотре и применении. В `revision` укажи ревизию самой карточки из `show ID --brief`, а номера строк считай с единицы от начала файла. Добавь одно или оба поля.

- `"sourceFooter": {"line": 42, "target": "Sources/Originals/Осмотр.md"}` сохраняет ссылку на первоисточник всей карточки в разделе «Источник карточки». Она должна стоять отдельной строкой после пустой строки в конце последнего датированного снимка под заголовком третьего уровня. От этой ссылки до конца раздела истории допустимы только пустые строки. Проверь, что её адрес из папки проекта ведёт к указанному файлу.
- `"wikiLink": {"line": 35, "old": "[[Notes/Осмотр#Вопросы]]", "new": "[[Notes/Осмотр#^question-1|Вопросы]]"}` исправляет одно точное вхождение в архивной копии. Сверь содержание целевого заголовка или блока с первоисточником. После переноса проверь и новый переход, и сохранённую цитату прежней строки.

Если основания для выбора адреса расходятся, покажи владельцу запись и возможные источники. Для применения передай ревизию нового предпросмотра в `--apply`.

При запросе на все проекты собери их ID через `list --type project --limit 20`, дочитывая страницы с `--offset`, пока `truncated` истинно. Зафиксируй одну дату проверки для всех проектов. У каждого предпросмотра своя ревизия. По окончании выполни [проверку хранилища](../brain-vault/SKILL.md#проверить-хранилище) и сверь ранее сохранённые ссылки.
